# CLAUDE.md

Guidance for AI assistants working in this repository.

Ingot is an open-source, whitelabel design system. It is a pnpm workspace
monorepo: `packages/tokens` (`@ingot/tokens`), `packages/react`
(`@ingot/react` — not `ui`, see ADR-0002), and two apps, `apps/storybook` and
`apps/docs`.

**Current state: scaffolding.** There are no components yet. Storybook and the
docs site are not installed — those folders hold a `package.json` and nothing
else.

## Stop — ADR-0003 is not written

ADR-0003 (token architecture) IS NOT WRITTEN. Its absence is deliberate. Do not
create semantic or component tokens, do not invent a tier structure, do not name
a token anything other than a raw primitive, until it exists. If a task appears
to require this, stop and say so.

## Who maintains this

The maintainer is a product designer, not a frontend engineer. Explain what a
command or file does, and why it is needed, before running or creating it.
Introduce every tool the first time it appears. Work in small steps and pause
for confirmation.

## Tokens

Every value in a component that affects its appearance belongs to the consumer,
not to us. Colour, spacing, size, radius, shadow, border width, font weight,
opacity, transition duration, z-index — all of it is theming surface, and all of
it comes from `@ingot/tokens`.

If you find yourself typing a literal value into a component, stop. Either a
token exists for it, or one is missing and must be added.

The only exceptions are values with no design intent — structural CSS that would
be meaningless to change: `0`, `100%`, `1px` for a hairline where no scale
applies, `position: relative`. If you are unsure whether something is an
exception, it is not. Add the token.

Ingot ships as a versioned package (ADR-0001). Consumers cannot edit component
internals — their only escape hatch is the theming API. A hardcoded value is
therefore not a shortcut. It is a permanent hole in what they are able to
change, and it is a bug.

Tokens are authored in W3C DTCG JSON under `packages/tokens/src/`.
`packages/tokens/dist/` is generated by Style Dictionary and git-ignored: never
edit it, and run `pnpm --filter @ingot/tokens build` before anything imports
from it.

## Before making architectural choices

Read `docs/decisions/` first. Those decisions are deliberate and their reasoning
is recorded. Do not reverse one without writing a new ADR — copy
`docs/decisions/0000-template.md` and take the next free number.

## Verifying your work

A change is not done until all four pass. They are exactly what CI runs.

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm format:check
```

If the change is one a user of the library would notice, run `pnpm changeset`
and commit the file it writes. See `CONTRIBUTING.md` for what counts as
breaking.

## Git

Never commit to `main`. It is protected and direct pushes are rejected. Create a
branch, then open a pull request with `gh`.

## Storybook vs docs

- **Storybook** (`apps/storybook`) — component states, variants, accessibility,
  visual regression.
- **Docs** (`apps/docs`) — concepts, tokens, guidelines, ADRs, theming, getting
  started.

## Deliberate guards — do not relax

Each of these exists for a recorded reason. Friction from them is intended.
Removing one because it is noisy is a regression, not a cleanup.

- Do not upgrade TypeScript major versions without first checking
  `typescript-eslint` compatibility. Type-aware linting must keep working.
  See `docs/decisions/0004-typescript-version.md`.
- `noUncheckedIndexedAccess`, `noUnusedLocals` and `noUnusedParameters` in
  `tsconfig.base.json` are deliberate choices, not defaults.
- If pnpm refuses an install because a version was published too recently, the
  default response is to wait, not to override. Version-specific exclusions
  only, never a blanket opt-out.
- The `gh` token deliberately carries the minimum scopes needed, nothing more.
  If a task requires a scope it does not have, ask the maintainer rather than
  assuming — and explain what that scope would permit, not just that it is
  needed.
